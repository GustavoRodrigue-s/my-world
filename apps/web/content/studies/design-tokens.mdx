Toda interface é feita de pequenas decisões: o vermelho dos links, o espaço entre dois parágrafos, a velocidade de um hover. Quando essas decisões ficam espalhadas pelo código — um `#B5321C` aqui, um `margin: 9px` ali —, elas começam a divergir sem que ninguém perceba. **Design tokens** são a forma de escrever cada decisão uma vez só, com nome, e deixar que todos os lugares a leiam dali.

## O que é um token

Um token é um par de **nome** e **valor**, com um tipo. O nome diz o papel; o valor diz como ele se parece hoje. O papel muda pouco; o valor pode mudar sempre.

- `color.primary` — a cor da marca, que de dia é rubrica e à noite é brasa;
- `space.4` — um degrau da escala de espaço, 16 pixels;
- `duration.fast` — 150 milissegundos, o tempo de um hover.

Quem usa o token não sabe o valor, e não precisa saber. Esse é o ponto: trocar o vermelho da marca vira a mudança de uma linha.

### Três camadas

É comum organizar os tokens em camadas, das mais concretas às mais abstratas:

1. **Primitivos** — a paleta e as escalas, sem significado: `color.rubric`, `color.graphite`.
2. **Semânticos** — o papel de cada valor num tema: `color.primary`, `color.support`.
3. **De componente** — exceções de um componente, quando existem. Quanto menos, melhor.

## O formato DTCG

O [Design Tokens Community Group](https://www.designtokens.org/) definiu um formato em JSON para que ferramentas diferentes leiam os mesmos tokens. Cada token tem `$value` e `$type`, e pode apontar para outro com chaves:

```json
{
  "color": {
    "$type": "color",
    "rubric": { "$value": "#B5321C" },
    "primary": {
      "$description": "a cor da marca",
      "$value": "{color.rubric}"
    }
  }
}
```

A referência `{color.rubric}` é o que permite as camadas: o tema não repete o valor, ele aponta para o primitivo. Se a rubrica mudar, o tema muda junto.

## Do arquivo aos lugares

O JSON sozinho não pinta nada. Uma ferramenta de build — aqui, o Style Dictionary — lê os arquivos, resolve as referências e escreve uma saída para cada lugar que precisa delas.

No CSS, cada token vira uma variável, e o Tailwind registra as variáveis como utilitários. O componente escreve `bg-primary`, nunca a cor:

```css
:root {
  --color-primary: #b5321c;
  --space-4: 1rem;
  --duration-fast: 150ms;
}
```

A tabela abaixo mostra o mesmo token passando por cada camada:

| Camada | Nome | Valor |
| --- | --- | --- |
| Primitivo | `color.rubric` | `#B5321C` |
| Semântico | `color.primary` | `{color.rubric}` |
| CSS | `--color-primary` | `#b5321c` |
| Utilitário | `bg-primary`, `text-primary` | `var(--color-primary)` |

## Um tema é só outro arquivo

Como o componente fala em papéis, trocar de tema é trocar os valores por trás dos nomes. Cada ambiente deste site tem o seu arquivo de tema, e a página de [identidade visual](/identity) mostra as cores de todos eles lado a lado.

A página não repete os códigos de cor: ela os lê dos mesmos tokens que o CSS usa.[^1] Se um valor mudar no JSON, a amostra muda junto.

> Uma regra só funciona se for mais fácil segui-la do que quebrá-la. Com tokens, o caminho mais curto já é o certo.

## O que se ganha

<Quote text="“A simplicidade é o último grau da sofisticação.”" source="atribuída a Leonardo da Vinci" />

- **Consistência** — o mesmo vermelho em todo lugar, sem caçar valores repetidos.
- **Temas baratos** — dia e noite, ou um ambiente novo, são um arquivo a mais.
- **Uma conversa só** — designers e programadores falam dos mesmos nomes.

O custo é a disciplina: um valor que não existe como token ganha um token antes de ser usado. Parece burocracia nas primeiras semanas; depois, é o que deixa o resto rápido.

## Conclusão

Design tokens não são uma ferramenta, são um hábito: dar nome a cada decisão visual e guardá-la num lugar só. O formato DTCG torna esse lugar legível por qualquer ferramenta, e um build como o do Style Dictionary leva a mesma decisão ao CSS, ao JavaScript e aos ícones.

O resultado é uma interface que muda inteira quando uma linha muda, e que não muda nada quando ninguém quis mudar. Para um projeto com mais de um ambiente, como este, é a diferença entre manter uma identidade e manter várias cópias dela.
